# Security Policy

## Reporting A Vulnerability

Use GitHub's private vulnerability reporting for this repository when that
feature is available. If the private reporting button is unavailable, open a
minimal public issue asking the maintainer to establish a private channel; do
not include exploit details or sensitive data in that issue.

Public issues and pull requests must not contain secrets, provider tokens,
private music-library paths, copyrighted audio, or private library databases.

## Scope

Security reports are especially useful for unsafe file replacement, path or
token disclosure, write-authority bypasses, stale-state validation failures,
and dependency vulnerabilities. General support questions belong in the issue
tracker without private data.
